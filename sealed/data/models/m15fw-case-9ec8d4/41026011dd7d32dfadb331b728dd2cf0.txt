这是对 METHOD.md 的补充，和 METHOD.md 一样，是你必须遵守的工作方式。下文说的「上一节」「按上一节闭合的主定理」，指你按 METHOD.md「第二步 · Lean 这一侧」交出的、在 Lean 里闭合的那条「到不了」主定理。

**要判定一关走得通还是走不通、并给出证明时，你可能会发现已有的规则缺少一些必要的元素和规律。**
把它们记录下来（`analysis/record.txt`）：已经能从语料确认的，现在就加进规则（先 `rule/`、再 Lean 的 `Rule/`，
照常在全部转移上判错）；还确认不了的，列成待测，在下一次 attempt 里通过探索去确认，确认之后再加进规则。
证明模型只用已经加进 `Rule/` 的规则。

### 自审：证完「到不了」以后，先查你的模型是不是比游戏更严

**主逻辑（先读这一段）。** 你证明了「到不了」，交出了一份在 Lean 里闭合的证明。这只说明**在你的模型里**到不了，
不说明游戏里也到不了，更不说明你报的最少代价（预算）是最紧的那个界。证明会原样继承模型的每一处偏差：

```
模型某条规则比游戏宽   模型允许的走法比游戏多       「到不了」在游戏里仍然成立；最少代价只会偏低
模型某条规则比游戏严   模型禁止了游戏允许的一步，   你的最少代价偏高，界不是最紧的；
                       或者多收了代价              「到不了」在游戏里可能是假的
                                                   —— 而证明本身发现不了：它对你的模型是对的
```

所以**闭合的证明不是终点**。过严是危险的方向，而且它最容易藏在你从没走过的情形里：正是你的模型告诉你
那边不值得走的地方。拿到闭合证明以后，要**逐条核验承重的规则有没有比游戏更严**，下面就是怎么核。

结论只和它依赖的那几条规则一样可靠。模型里大多数规则跟结论无关；有几条是**承重**的。
对这几条，「记录过的转移全都对得上」还不够：要紧的是游戏在**结论用到它们的那个情形**里是不是照办。
这一圈自审和上面的非空洞性测试不是一回事：那一条只放宽**一个**限制、证明前提是真约束；
这里要把**每一条**规则都朝「更容易到达目标」的方向放松一遍，看结论靠的是谁，再去游戏里查那几条。

**什么时候做（attempt 是有限的，探测要花 attempt）：**

```
触发     第一次拿到按上一节闭合的主定理，就在那次 attempt 的追问里做 (a)
         到第 4 次 attempt 结束还没有闭合证明：照样在第 4 次的追问里对当前最好的模型做 (a)，
         闭合证明接着做，探测从第 5 次 attempt 开始
探测     从下一次 attempt 起，每次 attempt 都先做 (b)，直到 (d) 满足；
         这样的 attempt 不必去争取到达目标
修改     (c) 在两次 attempt 之间的追问里做（不发动作）
做完     (d) 满足以后，剩下的 attempt 照常用
```

**(a) 规则敏感性（纸面，不发动作）**

以「每条规则都按证据所支持」的那份模型为准（不是定理里带自由未知量的弱化版）。
记 `L` = 它到达目标的最小代价，口径和你的结论一样；`C` = 本关测得的上限。

1. **列出模型的每一条规则。** 模型的 `step` 决定的每一件事都算一条，包括你觉得「只是编码」的那些。
   至少过一遍下面这几类，每类写出你模型里属于它的规则：

```
前提     动作什么时候被允许 / 有效果 / 被挡住
效果     动作改了什么（每个被改的量单独算）
收费     每个动作扣多少，以及每一条会改变已花或剩余数量的规则
常数     模型里每一个你拟合出来或读出来的数（阈值、数量、位置）
顺序     一个动作的几项效果按什么先后发生
终止     一关在什么情况下结束
抽象     证明的表示里丢掉或打包的东西（宏动作、不跟踪的状态、因为没见过而删掉的选项）
```

2. **只考虑你的记录允许的放松。** 一个放松只有在放松后的模型**仍然复现你记录过的每一条转移**
   （所有关、所有 attempt）时才算候选。和某条记录矛盾的放松已经被游戏否掉了，不要在它上面花搜索。
   每条规则往「只会让到达目标更容易」的方向，找出它能放松的范围：

```
现在的规则       模型现在怎么写
最宽可容许版本   仍然复现全部记录的转移的、这条规则最宽的写法（恰好放宽到记录钉住的地方为止）
```

   候选只在这两者之间。

   **一条规则通常不止一个能放松的地方。** 一条禁止、阻挡或收费的规则排除了好几种不同的情形，
   每一种没被记录钉住的情形都是一个单独的放松，逐个列成这条规则的子行（`R3.1`、`R3.2`、…）。至少过一遍：
   - **它检查的每一样东西**：一条检查好几个量的条件，可以在每个量上分别放松；
   - **这个情形能怎么出现**：同一个状态可以由不同种类的动作造成。从一种动作上学到的规则，
     对别的动作只是外推，所以每一种动作都单独算一个情形；
   - **每条记录过的反例，按最窄的读法**：一条「规则成立」的记录只在它那个确切的情形里钉住规则。
     一个放松如果在别处都允许、只在记录过的反例那里不允许 —— 也就是靠那些反例情形里的另一个量
     把它们区分开 —— 它仍然可容许。写明是哪个量，用重放来核。
   - **触发类规则：把整张表写出来。** 这类游戏里的规则大多是接触触发的（先验）：某个东西什么时候开始起作用、
     某个效果什么时候发生、碰到时状态怎么变。对这种规则，它的情形是下面三样的**组合**：
     （一）每一种能造成这个触发情形的动作（凡是能改变触发条件所看的那些量的动作都算）；
     （二）每一种接触的方式（挨着、部分重叠、完全盖住）；
     （三）行动者自身状态的每一种取值。
     把这张表写进 `pass1.md`，每一格标成三种之一：**已覆盖**（引那条记录的原文）、**未覆盖**、**到不了**。
     **没被覆盖的每一格都是一个没被钉住的情形**；一次「没触发」的记录只钉住它自己那一格。
     每个未覆盖的格子单独作为一个情形去放松，不同行、不同列的格子不要合并。
     **一格只有用你的模型做过可达性检查，才能标成「到不了」**：在模型的可达状态里搜，看有没有一个状态，
     从它出发这个动作会造成这种接触，并报出搜索本身（搜了什么、多少个状态）。搜到了，这一格就是到得了的：
     把那个状态和动作写下来，它就是这一格的咬合情形；没有记录覆盖它的话，这一格就是未覆盖。
     只凭判断（「这不会发生」「这种组合不可能」）不能标「到不了」；没做搜索的格子一律算未覆盖。

   每个情形给两档，写清放松的到底是什么、放松多少：

```
小步放松   可容许的最小改动：多一种情形下允许这个动作或让它生效；它收的少收一个单位；
           它用的常数朝有利方向挪一个单位；两项检查换个先后 —— 每一种都要仍然复现全部记录
最宽放松   最宽可容许版本
```

   可不可容许，要把记录过的转移拿到放松后的模型上**重放**来判，不靠估计。
   现在的规则已经就是最宽可容许版本（被记录钉死）的，写「被记录钉死」，引一两条钉住它的转移；
   这样的情形不用搜索，也不用探测；一条规则的**所有**情形都被钉死，这条规则才算被钉死。直接从画面上读出来的常数（物体的位置）被画面钉死。
   已经是最宽读法的规则（「宽松取向」）写明，没有放松档。
   其余规则一字不动，重算最小代价，记作 `L_小步`、`L_最宽`。

3. **写敏感性表** `work/selfaudit/pass1.md`，在下一次 attempt 发出第一个动作之前写好：

```
规则 | 类 | 小步放松（原文） | L_小步 | 最宽可容许放松（原文） | L_最宽 | 钉住它的记录 / 它凭的记录
```

   表头写 `L = …`、`C = …`，另列一小段「被记录钉死」的规则，各附钉住它的转移。
   每个情形一行。`L_小步 < L` 或 `L_最宽 < L` 的情形是**承重**的（放松它，最小代价就下降，**降多少都算**）。
   其中 `L_小步` 或 `L_最宽` `≤ C` 的单独标出：「到不了」的结论直接靠它们。
   **每个承重情形都要探测，包括放松后最小代价仍高于 `C` 的那些** —— 最小代价高了一个单位，结论照样是错的。

**(b) 在结论用到它的地方去探测承重规则 —— 用尽量少的动作和 attempt**

动作和 attempt 都有限，所以**默认不要按表的顺序一条一条测**。先认真想：哪几条最可能错，
哪些实验能一次测到最多条。

1. **咬合步。** 对每条承重规则，取放松后模型的最便宜路线（小步放松；最宽放松的路线不同时也取），
   找**咬合步**：放松后的模型和全证据模型第一次给出不同预测的那一步。写下那一步之前的状态、
   那个动作、两个模型各预测什么。这就是要把游戏带去的那个情形。
2. **按「多可能是错的」排序**，不只按它让 `L` 降多少。每条承重规则写一行：照你的记录看，它有多可能错：
   - 记录过的转移离它的咬合情形有多近？如果记录只覆盖了这条规则所看的东西的**其他取值**，
     那这条规则在咬合情形里是外推，外推最容易错。
   - 它是不是从一两次观测推广出来的？
   - 它是不是为了方便（编码、抽象）定下的，而不是从游戏里读出来的？
   按「可能错的程度 × 它能让 `L` 降多少」排探测顺序。开打之前把这个顺序和理由写下来。
3. **设计一次能测多条的实验。** 一个动作，如果它的结果在几条候选规则下各不相同，就能同时测这几条；
   一条路线，如果几个咬合情形共用前缀，就能一次走到好几个。开打之前：
   - 写一份**实验计划**：动作串，以及其中每一步转移测的是哪几条规则、每条规则各预测什么；
   - 优先选那种结果在几条候选规则下互不相同的动作（一次观测就能把好几个假设分开），
     以及在一次 attempt 的代价之内能走到好几个咬合情形的路线；
   - 最可能错的排在前面，万一这次 attempt 提前结束也先测到了它们；
   - **对照对。** 触发类规则还有没覆盖的格子时，最有信息量的实验是一对：**用两种不同的动作到达同一种接触方式**
     （或同一个动作、行动者处在两种状态）。一对分开一个因素；几对往往能排进同一次 attempt 的路线里。
   - 把计划写进那次 attempt 的押注里。
   最直接的单条探针是走放松后路线的前缀到咬合步，再做那个动作。前缀太贵，就设计一条更便宜的路，
   走到一个**在这条规则看的每一样东西上都和咬合状态一致**的情形，并说明其余的差别为什么和这条规则无关。
   一条记录过的转移只有在这条规则看的每一样东西上都是同一个情形时，才能顶替这次实验；用了就引原文。
4. 每条规则记结果：

```
CONFIRMED    游戏在咬合步照你的规则办
REFUTED      游戏照放松后的规则办（或做了别的你的规则不允许的事）
UNTESTABLE   你没办法让游戏面对那个情形；写清为什么（例如那个情形只在到达目标的那一步才出现）
```

5. **REFUTED 时不要停在这一次观测上。** 再设计实验（同样尽量一次分开多个假设），把这条规则成立过的
   情形（你的记录）和它失败的这个情形分开，直到你说得出改过的规则，以及它为什么也符合之前的每一次观测。

计划和每个实验的结果写在 `pass1.md` 表下面：测了哪几条规则、发了什么（第几次 attempt、哪几步）、
游戏做了什么（前后的值）、每条规则的结果。

**(c) 被驳倒的规则：修、重放、重新闭合**

照第 7 节修规则（凭哪一次观测、旧版挪进 NOTE）。改过的模型必须仍然**复现你记录过的每一条转移**，
包括探测时新走的；报出重放了几条、对上几条。然后按上一节在 Lean 里重新闭合，
重算 `L`，再做一遍 (a)，写成 `work/selfaudit/pass2.md`，以此类推。探测时新走的转移从此也算记录，
可能把原来没钉住的规则钉住。
之前已经 CONFIRMED 的规则，只有咬合步变了才需要重测。

**(d) 什么时候算做完**

最新一遍里的**每条承重规则都已经被实验 CONFIRMED**，或者记成 UNTESTABLE 并写明了理由。
attempt 用完时还有没测到的承重规则：最后的回答里逐条列出来，并报出把它们（以及所有 UNTESTABLE 的）
全部小步放松之后的最小代价 —— 让读的人看到你的结论有多少是靠游戏没被带去检验过的规则撑着的。
最后的回答里还要报：第一遍之前的 `L`、每一遍的承重规则、每个探针的结果、最后的 `L`。
