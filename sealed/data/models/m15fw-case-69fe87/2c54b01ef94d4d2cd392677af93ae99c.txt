# 方法：先把规则从实验里提出来，再把它变成对象 / 规则 / Lean

> 这一份是**要求**，不是建议。`README.md` 讲这个服务怎么用；这一份讲**你要怎么做**。
> 两份冲突时以 `README.md` 的约束为准（只走 HTTP、不出工作目录）。

和「随便玩玩然后交个结论」的差别只有一条：

> **你对这一关的任何主张，都要有一份你自己能核、别人也能核的东西撑着。**
> 画面看着像不算，试了几次没出事也不算。

这套方法分两步，**顺序不能颠倒**：

```
第一步  从实验里把规则**提出来、修对** —— 这一步占掉这一局的绝大部分时间
台架    概念怎么写、两道闸怎么关 —— **这个目录里的脚本强制的**，不是靠自觉
第二步  把规则**变成 Lean** —— 形式化，**收工时才做**
```

**先读第 8–12 节（台架）再动手。** 不知道闸在哪，第一个动作就会被拦下来。

**第一步没做完就进第二步，等于把猜测形式化。** 那会让猜测看起来像定理。

**跑的时候做第一步就够了。** 第二步（Lean 那一侧）在这一局结束之后才会要你交 ——
所以不要为了赶形式化而缩短实验。中途想写点 Lean 定义当笔记可以，但别让它挤掉探索。

**如果这个目录里已经给了你一份 `model/`**（见 `MODEL.md`）：
那份模型是**起手稿不是真值**，第一步对你来说就变成**验它、修它、补它** ——
办法完全一样，只是你不必从零发明规则。下面第 7 节专门说怎么改别人的规则。

**拿这套方法去帮你打通这一关。**

# 第一步：从实验里把规则提出来

下面这些不是建议清单，每一条后面都跟着「什么时候会翻车、翻车长什么样」——
那一半才是它值钱的地方。

## 0 开工之前的一次性投资

**0.1 先把观测坐标系钉死。** 拿一个坐标对去反查帧里那一格的实际颜色，
确认 `(a, b)` 是 `(x, y)` 还是 `(y, x)`。**定错了后面每一条规则都写反。**
带坐标的动作在顺序没定之前，先点对角线（两个分量相等）—— 这样把「坐标序」
和「点这里有没有用」两个未知拆开。

**0.2 一旦测出移动步长是 k 格，就把整帧折叠成格位图**，每格只报主色。
之后所有路径规划、「哪里是墙」「哪里有东西」都在这张图上看，不再逐格读帧。
折叠图一眼就露出地形、通路与标记，逐格读一张帧的开销是它的几十倍。

**0.3 跨约定的坐标不许靠眼睛搬运。** 两套分量顺序在数字接近时看不出差别，
而读错一次的失败模式**不是「算错了」，是凭空冒出一个不存在的现象** ——
那是最像重大发现、最会让你放下手头实验去追的东西。
判读不一致时，先用所有已知读法各读一遍，全读不通才准动结论。

## 1 怎么设计实验

**1.1 主动证伪，别等证据上门。**「什么条件下这一关会结束」这类规律，
很少会自己撞上反例 —— 因为你很少走到那个状态。对这类规律要**专门设计一段动作去撞它**。
形状：一族「怎样才算过关」的判断常年没被检验过，却一直当知识用着。

**1.2 优先走「两条已有规则给出相反预测」的那一步。** 它保证倒一条、也保证学到东西；
走两条都预测生效的路，最好的结果只是确认已知。

**1.3 连续几批零反例、而局面纹丝不动，是警告不是成功。**
说明你在反复确认已经知道的东西。去做一件你**不知道结果**的事。

**1.4 全部规则对某个候选动作都说不出话的那一步，是没人管的地图**，
不是已知规律的复查，值得优先走进去。

**1.5 绕不过去的时候，把失败本身当实验 —— 但要先押注。**
预算差几步、绕路也补不回来时，不要硬凑，也不要停下：
**先写一条关于「失败会长什么样」的可反驳预测，再走进去。**
押注必须写在动作之前，事后补写等于对着答案填空。
押「仪器会读出什么」，不押「世界是什么样」—— 只有前者可判。

## 2 读动作效果时最容易栽的几处

**2.1 动作被接受 ≠ 动作生效。** 至少三种结局：生效、被受理但没生效、完全不被受理
（前后两帧逐格相同）。把后两种并成「没生效」，和计数有关的规则一定会被推翻，
而且推翻的地方不告诉你真原因。

**「没生效」本身又分好几种成因，分开它们各要一步实验**：

```
键是死的        根本不认这个动作
有条件的        局面没摆到它的前提上
幂等的          当前值恰好已是它要设的值，做了等于没做
被吞掉的        世界刚被重新起头之后的第一个动作常常整帧无差
```

所以「这个动作没用」这个结论必须先过两问：
**局面摆到它的前提上了吗？这个结论在别的局面复现过吗？**

配套一条：一个「设成 X」型动作，在当前值已经是 X 的局面上按出来的空帧，**什么证据都不是**。
得专门在取值不同的局面上再测一次。

**2.2 先在空地上量全，再去窄处量阻挡。** 反过来做，会把地形的形状写进动作表。
还要把「这一步改了几样东西」和「这一步改了多少」分开问。

**2.3 把「这一步改了多少格」拆成整数和**（形如 总数 = 腾空 + 新占 + 计数器），再去猜语义。
格数能直接定出可动对象的尺寸、以及有没有搭便车的计数器，比从图样上猜快得多。
**每一项分开写、各带自己的依据，别写成一个总数** —— 总数错了你只知道「有地方不对」，
分项错了你知道是哪一项不对。

这一条有两种典型翻车：

```
① 那个「一直对」的常数项，只在无聊步上对。
   「新占 = 满格」隐含前提是「目标格是干净地板」，
   可**每一个值得走的步，按定义都是踩到不是干净地板的东西上**，
   于是这个常数专门在关键步上失效。
② 腾空那一侧同样不是常数：身下压着别的东西时，与自己同色的那些格不进帧差。
   被当成「吃掉了」的东西，可能只是被压住，走开后逐格恢复。
```

**2.4 别拿「帧差格数」当判据。** 阈值总是从某一次事件量出来的，换一档就静默失效。
改用结构判据（墙集合变没变、记号少没少），它们不依赖你没测过的量级。

**2.5 每次动作都会变一点的量**（计数器、进度条、资源），先问它依赖什么：
动作次数？只有生效的动作？某一类事件？**不要一上来就写死一个常数。**

**2.6 拿两三个点去外推第四个，是同一个病的另一副面孔。**
两个点能穿过无穷多条曲线。拿不出任何理由说明某个量为什么该跟关卡号走，
就不该把它写成关卡号的函数。找不到机制时，**把表写成表**，
并写明拟合用了哪几个点、还没考过的是哪几个点。
另外：一个「每步扣 q」的读数，往往等价于「本关的预算 = 某个总量 / q」——
**预算才是机制那一侧的量，被画出来的那条读数只是它的显示**。去量那个可能才是真变量的东西。

## 3 规则怎么写才可判错

**3.1 先声明作用域。** 这条规律是**本关之内**成立，还是**跨关**也成立？
没声明作用域，等于悄悄断言了「跨关也成立」—— 那是你还没验证过的强断言。
形状：换关那一步整批规则一起倒，因为它们全都默认了跨关。

**推论：换关之后不要沿用上一关量出来的任何常数。**
规则一条没倒（它们声明了作用域，是对的），倒的是**路线规划的全部算术** ——
而算术没人拦。进新关第一件事是把要用到的每个量重新量一遍。

**3.2 一条规则只许断言一件事。**「A 且 B」写在一起，倒的时候你不知道倒的是 A 还是 B，
会连带把还活着的那一半一起改掉。

**3.3 主张写成蕴含式（A ⇒ B）时，判据必须盖住 A 的每一种取值**，
不然「A 从没成立过」会被判成和「A 成立且 B 也成立」一样的通过。
**这个病最阴**：判据用了、只是漏了一支，代码看着完全正常，而且永远不报错。
把主张里每个「任何 / 所有 / 全部」圈出来，问代码靠什么认它 ——
答案要是「在我列出的那几样里」，那就是个洞。

**3.4 数出来的数属于主张，不属于前提。**「恰好 N 个」这类整数要写进主张去挨打，
不要写进判据的前提里。
否定式的作用域（「只要不是 X 就不变」）是在替所有你没见过的东西担保，
改成正面枚举，猜错的代价是弃权而不是错判。

**3.5 改到第三版还在挨打，就撤掉重写。** 那多半说明你问错了问题，而不是没修对。
撤掉不丢人，改到第七版才丢人。

**3.6 一条规则倒了的时候，先看同一批里没倒的那些** —— 它们是免费的约束，
能把未知量夹出来。别急着去要新证据，先把已有的断言当方程解。

## 4 防自欺

**4.1「到过」不等于「测到」。** 世界按你押的样子动了，不等于你验证了什么 ——
要问的是这条规则**被多少个它本来可能出错的局面考过**。
一条规则靠静默弃权（判据算不出来、返回「不适用」）撑着满分，是最常见的自欺。
报任何「零反例」之前，先报它弃权了多少次。

**4.2 收窄作用域会把样本压小；样本小到个位数时，错的机制也能拿满分。**
触发信号很具体：**改版理由里写着「某某情形不算」，并且改完样本只剩个位数**。
这时不要庆祝，要去问「有没有一个更简单的东西同时管住两边」。

**4.3 放宽作用域时，断言强度必须跟着降回证据支持的那一档。**
从邻居那里把更强的谓词原样搬过来，是最容易犯又最难自查的错 ——
因为**在邻居那里它是对的**：邻居的窄作用域恰好把反例挡在外面。
动手前问一句：这张证据当初是用哪个谓词统计的？断言不许比它更强。

**4.4 多步预测是推演，不是 N 个单步。**
把上一步的预测喂给下一步，得到的是**链口径**的分数；
每条规则各自的分数是**单步口径**（拿真实的上一帧算的）。两个数能差一个量级，混报等于自欺。
某一步塌了，先拿真实的上一帧对那一步单步重跑 —— 全对就说明损失全在链上，别去改规则。

**链子在没人说话的那一步断掉。** 某一块帧差没人认领，链子就把「不知道」压成「不变」，
从那一步起全部推理都在一张残帧上进行。**「不认领的格子被填成什么」必须有人负责**，
不写，实现会替你选，而且从不报错。

**4.5 空白有两种：「没人写」和「写不出来」，它们长得一模一样。**
碰到一整块没人管的地方，先分清是哪种；分不清就去写一次，写不出来的会自己撞上来。
写不出来的要**登记清楚被挡住的是哪一条具体主张** —— 只写「表达不了」，
下一个人会以为那只是没人写。

**4.6 服务不回答和服务不转发是两回事。** 动作发出去了但根本没到世界手里，
那一步什么都没被观测到；把它写成规则，就是把实现细节冒充成世界规律，
而且它永远判通过（世界从没有机会反驳）。

## 5 对账：先报后看

**拿你的规则预测下一帧，再真走一步对照。先写预测，再去走，再对比。**
反过来做（走完再解释）永远对得上，什么也证明不了。

**三个数都要报**：对账过多少帧、对上多少、对不上多少。
对不上的帧**不许删**，要逐条说清是规则错了还是你读错了。

## 6 丢掉机制的审计（进第二步之前必须做）

把你**观测到但没写进规则**的每一条机制列成一张表，逐条说方向：

```
丢掉它之后，模型**允许的迁移变多**  ⇒ 模型比真世界松，不会漏掉真走得通的路
                                   ⇒ **可以丢**（但要记下来）
丢掉它之后，模型**允许的迁移变少**  ⇒ 你把一条真能走的路从模型里删掉了
                                   ⇒ 模型会告诉你「这边走不了」而其实走得了
                                   ⇒ **不许丢**
```

自检：表里每一条都落在上面两行之一，没有「大概不影响」这种话。

**还要单独填这一行：动作可能没摸全。** 你见过的动作未必是全部。
没试过的动作、没试过的参数，列出来。

## 7 修规则（自己写的、别人给的，一视同仁）

一条规则和画面对不上的时候，有且只有三种可能，**先分清是哪一种再动手**：

```
① 你读错了      坐标序、折叠口径、把动画中间帧当成了稳定帧 —— 先排除这一类（见 0.3）
② 规则写窄了    它说的那一支是对的，只是还有别的支没写 —— 该**扩**，不是推翻
③ 规则写错了    它那一支本身就不对 —— 该**撤**
```

**最常见的是 ②，而最常被当成 ③。** 一条规则挨了打，先问「它说对了多少」。

改法四条，一条都不能省：

```
(a) 改之前先写下你凭哪一次观测认定它不对：哪一步、前后两帧差在哪、
    按旧规则该是什么样。**没有这一条就不许改。**
(b) 改完拿它在**你已经观测过的所有转移**上重跑一遍 ——
    对上的条数**不许变少**。变少了说明你修出了新毛病，那比原来的毛病更难发现。
(c) 旧版本不要删，挪进 NOTE 里，写清为什么撤。
    一条规则的改版史本身就是读数：改到第三版还在挨打，撤掉重写（见 3.5）。
(d) 改完回头看一眼这条规则的 `NOT_CLAIMED`：
    你刚补进去的东西，是不是正好是它原来声明「不主张」的那一块？
    是的话，把那一句也跟着改掉 —— 留着假话比没写更糟。
```

**别人给你的规则有一处要额外小心**：它的 `SCOPE` 和 `NOT_CLAIMED` 是**别人的**边界声明，
不是世界的性质。`NOT_CLAIMED` 密集的地方，通常正是那份模型最虚的地方 ——
那是线索，不是禁区。

# 台架：概念怎么写，两道闸怎么关

这不是建议，是**这个目录里的脚本强制的**。

## 8 一条概念的形状

一个文件一条，放 `concepts/<短名字>.py`：

```python
"""首行 docstring 就是主张，写成一句能被判错的话。**一条概念只断言一件事。**"""
LEVEL = "L1"          # 地图的哪一块：L1 动作效果 / L2 阻挡 / L4 计数器 / L5 终止 / L6 运动物 / L7 观测
SCOPE = "只看 ACTION1；换关返回 NA；定位不到返回 NA"
NOTE  = ""            # 改版时写清**为什么**改、被哪一步打了脸
EVIDENCE = ["…"]      # 它所依据的 tid，**不能为空**

from _lib import me, CELL      # 本局词汇：这些是假设，跟着概念一起被重审
from geo import diff_sum       # 跨局几何：里面没有任何关于世界的断言


def assert_(prev, action, nxt, ctx=None):
    """**检查器**：让主张可判错。只许返回 "TRUE" / "FALSE" / "NA"。"""
    ...


def apply(prev, action, ctx=None):
    """**生成器**（可选）：这条概念**敢生成**的那部分下一帧，只填它管得着的格子。

    返回 {(行, 列): 颜色} 或 None。
    """
    ...
```

**两半各管一件事，缺哪一半都有代价：**

```
只有 assert_         它只会判，不会生成 —— 对 E（规则图完成度）没有贡献
只有 apply           没有可判错的主张，等于没上闸
两半都有而口径不同    常有的事，而且**是好事**：
                    「判」比「生成」窄的概念活得久 —— assert_ 不看它让出去的格子，
                    apply 多画一格就多一次挨打的机会，两边的差是真线索
```

不变量式的概念（「墙集合不变」）生成不了就别写 `apply`。

`_lib.py` 是本局词汇（色号、边长、定位函数）。**它们是假设，不是事实**：
改 `_lib` 不算改版，但依赖它的概念要一起重审。两条概念都从同一个词取值再互相核对，
**S = 1 不等于这个词被检验过**；要检验一个词，得有一条概念拿它和帧上**另一种**读法对。

## 9 两道闸（脚本强制，不靠自觉）

```
闸一  **没有比最后一条转移更新的押注，`act` 发不出去。**
      python play.py bet "第几步、谁、变成什么样、依据哪条概念"
      只有整条命令就是 `act RESET` 才豁免。
      bet 和 act 是两条独立命令 —— act 在发之前查押注的时间戳，
      **事后补写等于对着答案填空**，闸会认出来。

闸二  **有没结算的转移、没处理的反例、跑不起来的概念，`act` 发不出去。**
      python play.py settle
```

**为什么闸关在发动作这一侧**：反例没处理就接着走，后面每一条转移都是在一个
已知错的模型上记的账，而**错不会自己报出来**。闸关在 `act` 上，
是让「修完再走」成为唯一能走的路。

出反例之后三条出路，**只有这些**：

```
· 改断言，改到在那条转移上判 TRUE；
· 缩 scope 判 NA（缩了就别再声称管那一片）；
· python play.py retire <名字> --why "……"   撤册，源码留进 history/
```

**把反例的 tid 抄进 EVIDENCE 只是登记，不是修好。**
结算会在这条概念自己的 EVIDENCE 上重跑 `assert_`，判 FALSE 照样关闸 ——
把打脸的那条抄进依据里，等于宣称「我是从它推出来的」，而它判自己错。

## 10 五条硬要求（缺一不入册，闸不开）

```
1  EVIDENCE 非空
2  assert_ 三或四参
3  返回值 ∈ {TRUE, FALSE, NA}
4  曾作为这条概念的反例披露过的 tid，必须在它的 EVIDENCE 里
5  它在自己 EVIDENCE 里的转移上**不许判 FALSE**
```

概念 import 失败 / 抛异常 / 返回值不合法，以 `error` 关闸同样处理：
**没被检验不等于没被推翻。**

## 11 报数纪律

结算每批打这几个数，**S 必须与 C、N、seen 同报**：

```
held_out(X)   全部去重转移 − X 自己声明的 EVIDENCE
N             held_out 上返回 TRUE 或 FALSE 的条数（NA 不算）
S             TRUE / N；N = 0 时记 UNMEASURABLE
C             N / |held_out|，**覆盖率**
seen          held_out 里曾因别的概念作为反例披露给你的转移数（污染量，显式报，不剔除）
```

**只报 S 是在报一个把分母藏起来的数。** S = 1 而 N = 3 的概念，和 S = 0.95 而 N = 200 的，
不是一回事；前者多半是 scope 被收窄之后剩下的几个样本恰好对称（见第一步 4.2）。

`apply` 那一侧只报不拦：

```
P      这条概念预测的格子里对了多少
E      **规则图完成度** —— 帧差里被解释的格子占比。**唯一一个写得越多越涨的数**
冲突   两条概念对同一格给了不同颜色 —— **那一步优先去走**（见第一步 1.2）
残差   没人预测对的格子 —— 地图上没人管的地方
```

## 12 一轮长什么样

```
python play.py reset
python play.py status                 # 看两道闸通不通
python play.py bet "……"               # 闸一
python play.py act ACTION1 ACTION1    # 发动作，自动记转移
python play.py settle                 # 闸二：判、报数、出反例
   ├─ 有反例 → 改断言 / 缩 scope / retire，然后再 settle
   └─ 闸开   → 回到 bet
python play.py retire <名字> --why "……"
```

走一步就结算、走十步再结算都行。一个好用的边界是
**押注里最没把握的那一条兑现或落空之后**。

# 第二步：把规则变成对象 / 规则 / Lean（**收工时才做**）

这一步在这一局结束之后做，不要在跑的时候抢时间做。
第一步交出来的是一堆经得起打的规则，这一步把它们变成可判错的结构。

```
1. 提对象     盘上有哪些「东西」，每个东西有哪些「位」
              自检：每个对象都说得出「拿掉它，哪一对局面从能区分变成不能」

2. 长规则     每条规则写成一个**函数**：给定局面和动作，它改了什么
              自检：每条规则的论域可执行（你能说出它在哪些局面上适用）

3. 简化       删掉没有任何规则读过的位；合并判决永远一致的规则
              自检：删完之后，你的模型对**已观测的每一帧**的判决一个字不变

4. 形式化     把对象和规则**写成 Lean 定义**（不是定理）
              自检：每条规则恰好落一种身份 —— 定义 / 由定义推出的推论 / 明写「不进模型」

5. 用它       拿模型去规划，再去真走。预测对不上就回第一步的第 5 节。
```

（如果 `model/` 已经给了你对象层和规则层，这一步就是**把你改过的那些落实回去**，
而不是重写一套。）

## Lean 这一侧

`lean/` 里有两个**泛型骨架**，已经编过、公理表干净。你要做的是**实例化**它们，不是重写。
两份都不含任何一局的事实。

```
lean/Skeleton1.lean   守恒量：存在 P，所有动作都保持 P
lean/Skeleton2.lean   单调量：存在 Φ，每个动作最多让 Φ 变 1
lean/Selftest.lean    一个小例子，示范怎么实例化（也示范了非空洞性测试怎么写）
```

怎么编（**不依赖 mathlib**，裸 `lean` 直编）：

```bash
# **工具链必须钉死。** 不要用 `ls … | head -1` —— 那样会挑到 v4.28.0，
# 它曾经把四条定理悄悄算成带 `sorryAx` 的，而编译**不报错**。
LEAN=~/.elan/toolchains/leanprover--lean4---v4.34.1/bin/lean.exe
"$LEAN" --version          # 先确认打出来是 4.34.1
cd lean
"$LEAN" -o Skeleton1.olean Skeleton1.lean              # 骨架一
LEAN_PATH=. "$LEAN" -o Skeleton2.olean Skeleton2.lean  # 骨架二（它 import 骨架一）
LEAN_PATH=. "$LEAN" Selftest.lean                      # 样板，应当全绿
LEAN_PATH=. "$LEAN" YourFile.lean                      # 你自己那份
```

### 四条硬纪律

1. **不许 `sorry`**，一处都不许。
2. **不许 `native_decide`** —— 它往公理表里塞 `ofReduceBool` / `trustCompiler`。
   用 `decide` 或 `rfl`。
3. 每条定理后面写 `#print axioms <定理名>`，**公理表只许出现
   `propext` / `Quot.sound` / `Classical.choice`，或者「不依赖任何公理」**。
4. **非空洞性测试**：一条永远用不上的定理也会编过 —— 前提永假时它恒真而毫无内容。
   所以每条主定理旁边都要有一条**方向相反**的，证明那个前提确实是约束。
   `Selftest.lean` 里那三条（用得上 / 方向没反 / 前提是真约束）就是样板。

`mathlib` **没有**。`by_contra` / `omega` 之外的很多常用 tactic 不在 core 里 ——
`omega` 在，`by_contra` 不在。

# 留下什么

`work/` 是你自己的地方，想怎么放都行。但跑完要能拿得出来：

```
· 第一步的产物：规则表（每条的作用域、依据、被多少局面考过、弃权过多少次）
· 丢掉机制的那张审计表
· 对账的三个数：对过几帧、对上几帧、对不上几帧，以及对不上的那几帧怎么解释的
· 第二步的产物：对象表、Lean 文件，以及每条定理的 `#print axioms` 原文输出
```

**这些比「结论对不对」更要紧。** 要量的不是你猜得准不准，是你的主张能不能被别人核。
