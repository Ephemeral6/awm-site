## c. Simplify
- The bar drawing was replaced by the action count `used`.
- Hint display was dropped: no rule reads it.
- Size was dropped: shrink is not modelled, so the side is always 4.

Check against observations: I ran the L4 moves I observed through the model by hand. They agree, including the blocked U that still turns the piece (21,29)→(21,29) face U. The three observed failing 6-matches are false under trigH6 (`obs1..3`). There is no automated replay of all 83 frames.

## Drop direction
Dropping shrink, teleport, the e-marker and the first-move no-op makes the model **stricter** than the game: it has fewer transitions. So `closed_never_wins` is only "impossible in model", and it does not transfer to the game. The positive theorem `route_wins` transfers only if (1) every transition on the route behaves as modelled and (2) `trig sPre = true` in the real game.

# Amendment, attempt 2 (Lean: namespace L4.V2 in lean/L4Model.lean; L4 v1 kept as the record)
- piece: new slot `size` (4|2). Without it, the 4x4 block at (25,37) and the 2x2 block at (25,37) cannot be told apart, yet one moves 4 per step and the other 2.
- `sel`: DROPPED. H6 was refuted: the panel was clicked and the match at sPre still did not open the barrier. No rule reads `sel` now. The key-panel click is a free no-op.
- MATCHF: definition. Size 4 → 2, top-left kept (attempt 2). Size 2 → 1 is NOT IN MODEL (never observed).
- MOVE / GOAL: definitions, generalised to side n.
- floor: the opened barrier and the 6-box both become floor.
- MATCH6: `trig` is still a parameter. Measured rule H5 = `face U ∧ c = 31` (trigH5). The theorem uses only `trig ⇒ c = 31`, which is looser than H5.
- Budget: a parameter LIM. Measured value 15.
- NOT IN MODEL: re-grow, the e-marker, size-1 halving, the first-move no-op, ACTION5/7.

Main theorem L4.V2.never_wins: for every LIM ≤ 19 and every trig with trig ⇒ c=31, no action list wins.
Non-vacuity: L4.V2.route26_wins (LIM = 26, trigH5); route26_short (the same route at LIM = 25 does not win).

# Amendment, attempt 3 (Lean: lean/L4ModelV3.lean, namespace L4.V3; imports L4Model)
- **rule MATCHF revised:** it toggles 4↔2. The grow anchor was observed once as bottom-right kept ((33,23)→(31,21)). The model allows 5 anchors nondeterministically (looser).
- **new object e-marker** (34-35, 23-24), slot `rf`. **New rule REFILL:** a 2x2 move whose slide footprint touches the marker sets rf and k := min(k+1-10, 5) (looser of the two readings of one sample). A 4x4 covering it gives no refill (observed).
- **Budget re-measured in units:** move = 1, match click = 2, other clicks = 1, B = 18. This fits every bar reading of all 3 attempts. The V2 budget (15 actions) is superseded.
- **Abstraction:** match = one macro action (F = 5, M6 = 4). This is sound as a lower bound because every match resets the grid, clicks never move the block, and the trigger reads the position at the completing click.
- **MATCH6 trigger:** c = 31 for any size and facing (looser than H5). The `face` slot is dropped.
- **Exact-match rule confirmed** (the superset {1,3,4,5,7} did not fire). This is consistent with the macro abstraction.
- **Proof method:** work/table4.py computes the least spent budget g(s) for all 1489 states reachable within 18 under the loose rules. Lean (`checkPart*`, decided by kernel) checks every transition against g. The win move needs g+1 > 18. MAIN: L4.V3.never_wins.
