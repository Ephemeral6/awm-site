Click buttons to move liquid between tanks; the level is won when every cursor's liquid is level with its mark.

The certified run that cleared every level, one action at a time. Beside each step: the rules of the model that explain it; they are also marked in the rule list below.

Explained by

Press Play or step to load the run. Keys, while the player is on screen: ← → step, Space play / pause. A click is circled; cells that changed are outlined.

How it plays

Black dividers cut the screen into several tanks, and the white is liquid. Blue buttons sit on either side of a divider, each belonging to the tank on its side; a coloured cursor sits at the front of the liquid surface in its tank; coloured marks set into a divider show the depth the cursor of the same colour has to reach. Clicking a button moves one portion of liquid from the tank across the divider into this one; a portion equals the thickness of that divider. If the far tank holds less than a portion, or this tank would overflow, the click does nothing. The light grey segments in a divider are gauges: a gauge lights up when the liquid on both sides is at its starting depth, and clicking a lit gauge sends each of the two cursors to the other side. The level is won when the liquid in each cursor's tank is level with the mark of the same colour and that tank touches the divider that carries the mark. The total amount of liquid never changes, and the height of the walls limits how much a tank holds.

Model

The final model: 9 object types and 10 rules. Each rule is a Python check against every recorded step; 7 of them are translated into Lean (the paper's per-game table). Code under a rule is the file of the same name in the agent's Lean project.

Object types

  • Dividers bandsBlack walls: which lanes they occupy, how thick, and how high they are drawn.
  • Tanks zonesThe spaces cut out by dividers that hold liquid.
  • Buttons buttonsBlue blocks beside a divider, each belonging to the tank on its side.
  • Target marks targetsColoured marks in a divider showing the depth the same-colour cursor must reach.
  • Gauges gaugesLight grey segments in a divider with no cursor of the same colour.
  • Liquid levels levelsHow deep each tank is filled right now.
  • Cursors cursorsSmall coloured handles at the front of the liquid surface in their tank.
  • Gauge display gauge_lookWhether each gauge is lit or dark right now.
  • Top bar usedThe top row of the screen, counting cells spent this level.

def pressWith (b : Board) (s : State) (gain lose st : Nat) : Option State :=
  if gain = lose then none
  else if s.levels.length ≤ gain then none
  else if s.levels.length ≤ lose then none
  else if getN s.levels lose - zoneLo b lose < st then some s
  else if capacity b gain < getN s.levels gain + st then some s
  else some { s with levels := bump (bump s.levels gain (· + st)) lose (· - st) }

def sendOver (b : Board) (z0 z1 : Nat) (c : Cursor) : Option Cursor :=
  if Nat.beq c.zone z0 || Nat.beq c.zone z1 then
    let dst := if Nat.beq c.zone z0 then z1 else z0
    match nth b.zones dst with
    | none => none
    | some z =>
      if Nat.blt z.lanes.size c.width then none
      else some { c with zone := dst, lane := landLane b dst c.width }
  else some c

def sendAll (b : Board) (z0 z1 : Nat) : List Cursor → Option (List Cursor)
  | [] => some []
  | c :: cs =>
    match sendOver b z0 z1 c, sendAll b z0 z1 cs with
    | some c', some cs' => some (c' :: cs')
    | _, _ => none

def clickGauge (b : Board) (s : State) (i : Nat) : Option State :=
  match nth b.gauges i with
  | none => none
  | some g =>
    match sides b g.band (some g.depths) with
    | [z0, z1] =>
      if aligned b s i then
        match sendAll b z0 z1 s.cursors with
        | none => none
        | some cs => some { s with cursors := sortC cs }
      else some s
    | _ => none

theorem pressWith_sum (b : Board) (s s' : State) (gain lose st : Nat)
    (h : pressWith b s gain lose st = some s') : sumL s'.levels = sumL s.levels := by
  unfold pressWith at h
  split at h
  · cases h
  rename_i h1
  split at h
  · cases h
  rename_i h2
  split at h
  · cases h
  rename_i h3
  split at h
  · cases h; rfl
  rename_i h4
  split at h
  · cases h; rfl
  rename_i h5
  cases h
  show sumL (bump (bump s.levels gain (· + st)) lose (· - st)) = sumL s.levels
  have hl1 : lose < (bump s.levels gain (· + st)).length := by rw [bump_length]; omega
  have e2 := sumL_bump (bump s.levels gain (· + st)) lose (· - st) hl1
  have e1 := sumL_bump s.levels gain (· + st) (by omega)
  have g2 : getN (bump s.levels gain (· + st)) lose = getN s.levels lose :=
    getN_bump_ne s.levels gain lose (· + st) (fun e => h1 e.symm)
  rw [g2] at e2
  try simp only at e1 e2
  omega

theorem pressButton_sum (b : Board) (s s' : State) (i : Nat)
    (h : pressButton b s i = some s') : sumL s'.levels = sumL s.levels := by
  unfold pressButton at h

  · cases h
  · exact pressWith_sum b s s' _ _ _ h

theorem clickGauge_levels (b : Board) (s s' : State) (i : Nat)

def CapOK (b : Board) (s : State) : Prop := ∀ k, k < s.levels.length → getN s.levels k ≤ capacity b k

theorem pressWith_cap (b : Board) (s s' : State) (gain lose st : Nat)
    (hc : CapOK b s) (h : pressWith b s gain lose st = some s') : CapOK b s' := by
  unfold pressWith at h
  split at h
  · cases h
  rename_i h1
  split at h
  · cases h
  rename_i h2
  split at h
  · cases h
  rename_i h3
  split at h
  · cases h; exact hc
  rename_i h4
  split at h
  · cases h; exact hc
  rename_i h5
  cases h
  intro k hk
  show getN (bump (bump s.levels gain (· + st)) lose (· - st)) k ≤ capacity b k
  have len1 : (bump s.levels gain (· + st)).length = s.levels.length := bump_length _ _ _
  have hk' : k < s.levels.length := by
    have : (bump (bump s.levels gain (· + st)) lose (· - st)).length = s.levels.length := by
      rw [bump_length, len1]
    simp only at hk
    omega
  by_cases hkl : k = lose
  · subst hkl
    rw [getN_bump_eq _ _ _ (by rw [len1]; omega),
        getN_bump_ne s.levels gain k (· + st) (fun e => h1 e.symm)]
    have := hc k hk'
    try simp only
    omega
  · rw [getN_bump_ne _ lose k _ hkl]
    by_cases hkg : k = gain
    · subst hkg
      rw [getN_bump_eq _ _ _ hk']
      try simp only
      omega
    · rw [getN_bump_ne _ gain k _ hkg]
      exact hc k hk'

theorem pressButton_cap (b : Board) (s s' : State) (i : Nat)
    (hc : CapOK b s) (h : pressButton b s i = some s') : CapOK b s' := by
  unfold pressButton at h
  split at h
  · cases h
  · exact pressWith_cap b s s' _ _ _ hc h

theorem pre_cap (b : Board) (s s' : State) (a : Act) (hc : CapOK b s) (h : pre b s a = some s') :
    CapOK b s' := by
  rcases pre_cases b s s' a h with e | ⟨i, hp⟩ | ⟨i, hg⟩
  · rw [e]; exact hc
  · exact pressButton_cap b s s' i hc hp
  · have e := clickGauge_levels b s s' i hg
    intro k hk
    rw [e] at hk ⊢
    exact hc k hk

theorem tank_cap (b : Board) (s s' : State) (a : Act) (hc : CapOK b s) (h : step b s a = .ok s') :
    CapOK b s' :=
  pre_cap b s s' a hc (step_ok_pre b s s' a h)

Before you start: our run of this check took 30 s and 1.7 GB of memory at its peak (2026-10-24).

  1. Download vc33.zip and unpack it. The model and its theorems are in archive/vc33-20260907/formal/Game.lean. Before changing it, check that its SHA-256 is

  2. Install Lean with elan, then the version named in the archive's lean-toolchain:
    elan toolchain install leanprover/lean4:v4.34.0
  3. Copy the model file to Check.lean and append these two lines to the copy:
    #print axioms consistent
#print axioms faithful
  4. In the folder that holds Check.lean, run:
    lean +leanprover/lean4:v4.34.0 -M60000 Check.lean
  5. Lean should finish without errors and print:
    'consistent' depends on axioms: [propext]
'faithful' depends on axioms: [propext]

What a pass establishes

consistent: for every recorded transition, as read by the agent's parser and with duplicates removed, every rule whose condition holds also has its effect hold. faithful: the certified run, recomputed step by step from the first screen of each level, matches the record and ends in a win. Axioms used: propext, all among Lean's standard ones.

What it does not establish: that the parser reads the screens correctly (that step runs in Python, outside Lean), or that a rule whose condition never occurs in the record is right. The Python file that produced the readings inside the model file is in the archive at meta/repair-20260928/lib/vc33-20260907/_lib.py.
