Peg solitaire: click pegs to jump and capture, and win a level when only one peg is left.

10 levels · 11 rules · all levels replayed in Lean

Replay

The certified run that cleared every level, one action at a time.

Press Play or step to load the run. Keys, while the player is on screen: ← → step, Space play / pause. A click is circled; cells that changed are outlined.

How it plays

This is a game of peg solitaire. The light grey cells are holes and the green round pieces are pegs. Click a peg to select it; grey rings appear on the cells it can jump to. Click one of the rings and the peg jumps over the adjacent cell and lands there; if the cell it jumps over holds a peg, that peg is captured. The level is won when only one peg is left, counting pegs outside the view. The board is split into several pieces joined by black rails; the arrow keys move the orange cart on a rail one step along it, the peg in the cart moves with it, and the camera scrolls with the loaded cart. Red and blue pegs can also be selected and can jump, but they do not capture what they jump over; purple stones sit on holes, and a peg can jump over them. When a jump leaves a dead position, a large disc appears in the lower-left corner; the undo key takes back the last move.

Model

The final model: 12 object types and 11 rules. Each rule is a Python check against every recorded step; 10 of them are translated into Lean (the paper's per-game table). Code under a rule is the file of the same name in the agent's Lean project.

namespace Game

def jumpTo (b : Board) (c : Core) (p : Nat) (d : Dir) : Option Nat :=
  match b.nbr p d with
  | none => none
  | some m =>
    match b.nbr m d with
    | none => none
    | some t =>
      if has c.pieces m && has (floorOf b c) t && !has c.pieces t then some t else none

def targets (b : Board) (c : Core) (p : Nat) : Rings :=
  [Dir.up, Dir.down, Dir.left, Dir.right].foldl
    (fun acc d => match jumpTo b c p d with
      | some t => acc ||| bit t
      | none => acc) 0

def selectable (c : Core) (p : Nat) : Bool := has c.pegs p || has c.greys p || has c.darks p

def canSelect (b : Board) (c : Core) (p : Nat) : Bool := selectable c p && targets b c p != 0

def select (c : Core) (p : Nat) : Core := { c with sel := some p }

def ringsOf (b : Board) (c : Core) : Rings :=
  match c.sel with
  | some p => targets b c p
  | none => 0

namespace Game

def middle (p t : Nat) : Nat := (p + t) / 2

def moveOne (p t : Nat) (x : Mask) : Mask := if has x p then diff x (bit p) ||| bit t else x

def jump (c : Core) (t : Nat) : Core :=
  match c.sel with
  | none => c
  | some p =>
    { c with
      pegs := if has c.pegs p && has c.pegs (middle p t)
              then diff (moveOne p t c.pegs) (bit (middle p t))
              else moveOne p t c.pegs
      greys := moveOne p t c.greys
      darks := moveOne p t c.darks
      stones := moveOne p t c.stones
      sel := none }

def isJump (b : Board) (c : Core) (q : Nat) : Bool :=
  match c.sel with
  | some p => has (targets b c p) q
  | none => false

def prune (w : Nat) (carts : Mask) (d : Dir) : Nat → Mask → Mask
  | 0, cand => cand
  | f + 1, cand =>
    let blocked := cand &&& shiftD w (diff carts cand) d.opp
    if blocked == 0 then cand else prune w carts d f (diff cand blocked)

def movers (b : Board) (c : Core) (d : Dir) : Mask :=
  prune b.w c.carts d 32 (c.carts &&& shiftD b.w b.rails d.opp)

def ride (w : Nat) (mv : Mask) (d : Dir) (x : Mask) : Mask :=
  diff x (x &&& mv) ||| shiftD w (x &&& mv) d

def pushCarts (b : Board) (c : Core) (d : Dir) : Core :=
  let mv := movers b c d
  { c with
    carts := ride b.w mv d c.carts
    pegs := ride b.w mv d c.pegs
    greys := ride b.w mv d c.greys
    darks := ride b.w mv d c.darks
    stones := ride b.w mv d c.stones
    sel := if mv == 0 then c.sel else none }

  1. Download lf52.zip and unpack it. The model and its theorems are in archive/lf52-20260920/formal/Game.lean. Before changing it, check that its SHA-256 is
    888f93639f4854f82ba3e93534ad14fcf20ad6323786d58105818bd279ae0e1d
  2. Install Lean with elan, then the version named in the archive's lean-toolchain:
    elan toolchain install leanprover/lean4:v4.34.0
  3. Copy the model file to Check.lean and append these two lines to the copy:
    #print axioms consistent
#print axioms faithful
  4. In the folder that holds Check.lean, run:
    lean +leanprover/lean4:v4.34.0 -M60000 Check.lean
  5. Lean should finish without errors and print:
    GUARD_HITS click_selected_peg_noop=3,click_selects_peg=384,click_switches_selection=6,click_stuck_peg_deselects=40,click_ring_jumps=187,jump_over_step_captures_nothing=101,grey_jumps_and_eats_nothing=39,stone_moves_when_no_peg_selected=26,click_dead_hole_inert=44,click_step_inert=6,click_outside_board=23,non_click_keys_inert=752,keys_clear_selection_iff_board_moved=18,disc_click_consumes=5,disc_only_at_the_killing_move=2884,no_disc_on_already_dead_position=723,levelup_needs_capture_jump=2905,levelup_is_two_peg_capture=165,loaded_cart_column_pinned=459,action7_undoes_one_move=91,cart_moves_iff_rail_ahead=1107
'consistent' depends on axioms: [propext]
'faithful' depends on axioms: [propext]
    The first line is printed by the file itself: for each rule, how many recorded transitions meet its condition.

What a pass establishes

consistent: for every recorded transition, as read by the agent's parser and with duplicates removed, every rule whose condition holds also has its effect hold. faithful: the certified run, recomputed step by step from the first screen of each level, matches the record and ends in a win. Axioms used: propext, all among Lean's standard ones.

What it does not establish: that the parser reads the screens correctly (that step runs in Python, outside Lean), or that a rule whose condition never occurs in the record is right. The Python file that produced the readings inside the model file is in the archive at meta/repair-20260928/lib/lf52-20260920/_lib.py.
