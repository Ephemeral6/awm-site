How it plays

Coloured ceramic tiles are laid on a grid, with several arrows around it and a few sockets, each marked with the colour it wants. Click one arrow, and the colours at a fixed set of positions are moved once as a whole: a run on a belt moves one cell, a star's ring or ray turns one cell, and swap buttons swap in pairs. Which cells are moved, and where to, is decided by the layout, regardless of the colours at the time; a click away from an arrow leaves the picture unchanged. When every socket is matched with the colour it wants, the level is cleared. Colours only change places, and the number of tiles of each colour never changes. The counter bar on the left records the number of arrow hits in this level; clicking on empty space does not count.

Model

The final model: 6 object types and 6 rules. Each rule is a Python check against every recorded step; 4 of them are translated into Lean (the paper's per-game table). Code under a rule is the file of the same name in the agent's Lean project.

Re-run the proof

Before you start: our run of this check took 210 s and 11.7 GB of memory at its peak (2026-10-24).

  1. Download lp85.zip and unpack it. The model and its theorems are in archive/lp85-20260907/formal/Game.lean. Before changing it, check that its SHA-256 is
    d87130ce3c1de9d137813d8fec0e4c075860a492a30b9cd1548db92985a04cc1
  2. Install Lean with elan, then the version named in the archive's lean-toolchain:
    elan toolchain install leanprover/lean4:v4.34.0
  3. Copy the model file to Check.lean and append these two lines to the copy:
    #print axioms consistent
#print axioms faithful
  4. In the folder that holds Check.lean, run:
    lean +leanprover/lean4:v4.34.0 -M60000 Check.lean
  5. Lean should finish without errors and print:
    'consistent' depends on axioms: [propext]
'faithful' depends on axioms: [propext]

What a pass establishes

consistent: for every recorded transition, as read by the agent's parser and with duplicates removed, every rule whose condition holds also has its effect hold. faithful: the certified run, recomputed step by step from the first screen of each level, matches the record and ends in a win. Axioms used: propext, all among Lean's standard ones.

What it does not establish: that the parser reads the screens correctly (that step runs in Python, outside Lean), or that a rule whose condition never occurs in the record is right. The Python file that produced the readings inside the model file is in the archive at meta/repair-20260928/lib/lp85-20260907/_lib.py.
